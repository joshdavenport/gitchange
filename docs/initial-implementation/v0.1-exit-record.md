# v0.1 exit record

Discharges the exit criteria of issue #36 (parent: #21). Everything here
was gathered at commit `54af01c` (benchmarks) / `5a19b68` (docs), on
2026-07-31.

## 1. Benchmark record

Two full `cargo xbench` runs, same commit, same matrix:

- [`docs/perf/report.md`](../perf/report.md) — Apple M1 Max (Darwin
  arm64), the dev-machine run; `results.csv` alongside.
- [`docs/perf/report-ci-ubuntu.md`](../perf/report-ci-ubuntu.md) —
  ubuntu-latest via the manual `Bench` workflow (run 30634046880), the
  "weaker hardware" run; `results-ci-ubuntu.csv` alongside.

### Scaling shape per dimension

Exponents are the machine-independent payload (`t ~ scale^k`,
least-squares over the graduated rows):

| dimension | M1 Max | ubuntu-latest | reading |
|---|---|---|---|
| files (10→1000 changed) | ^0.97 | ^0.97 | linear |
| hunks/file (2→128) | ^0.33 | ^0.57 | sub-linear; per-file overhead dominates |
| dormant records (1k→16k) | ^0.53 | ^0.66 | sub-linear; state-file parse per refresh |
| huge-file lines (32k→512k) | ^1.03 | ^1.05 | linear time |
| changed binary MB (8→512) | ^0.97 | ^1.00 | linear; byte throughput bound |

No dimension misbehaves: nothing super-linear anywhere, on either host.
The worst single step is 1.08 (huge-file 128k→512k on ubuntu).

### The huge-file memory probe (ADR 0005's unbounded-diff caveat)

Confirmed and quantified. Both diffs load rewritten content in full:

- M1 Max: an 81.8 MB single-file rewrite peaks at **790 MB RSS** (~9.7×
  content). Staging one huge rewrite and layering a second over it
  (`huge-128k-staged`, content through both diffs) is 1.78× time and
  ~1.5× peak RSS.
- ubuntu: same shape, 397 MB peak for the same content (~4.9× — RSS
  accounting differs across OSes; the multiplier's order of magnitude is
  the point, not the digit).

Binary files do **not** share this hazard: the ADR 0009 worktree hash
streams from disk, so 512 MB of changed binaries holds RSS flat
(~7-14 MB); peak RSS rides the largest single changed binary
(`binary-8x32m`: 32 MiB files → ~69-104 MB), not the total.

### Which cost dominates

**Diffing, almost everywhere.** The unassigned twins (same diff, no
changelists, matcher does no record work) sit at 0.92-0.98× of the
assigned baseline at 1000 files — the matcher is invisible at ordinary
shapes. It only becomes visible at pathological hunk density (128
hunks/file: 16-30% of refresh). A genuinely-changed refresh
(`files-250-touched`: re-match + state persist inside the timer) is just
1.06-1.14× of steady state. **With large changed binaries in play,
hashing swamps both**: ~5.4 ms per MiB changed on both hosts (~2.7 s per
refresh at 512 MB).

Mitigation ordering, if any ADR 0005 mitigation is ever un-gated:
**skip/lazy huge files first** (strongest evidence: linear time is fine,
the ~10× memory multiplier is not), then capped diff context; incremental
matching has no supporting evidence at any measured shape.

### Comfortable up to

With a 500 ms debounce and 5 s degraded poll, a refresh at or below
~300 ms is imperceptible. On both hosts, v0.1 is comfortable up to,
per refresh:

- **~1,000 dirty text files** (4,000 hunks): 270 ms M1 / 95 ms ubuntu.
- **any realistic hunk density**: 128 hunks/file × 25 files is ≤ 29 ms.
- **~16,000 dormant records**: adds ≤ 65 ms; parse cost, sub-linear.
- **single-file rewrites to ~20 MB**: ≤ 190 ms and ≤ ~220 MB peak RSS.
  An ~80 MB rewrite still refreshes in well under a second but costs
  ~0.4-0.8 GB of memory — that, not time, is the huge-file line.
- **~50 MB of changed binary content** (~270 ms). Hashing is linear at
  ~5.4 ms/MiB, so 512 MB of churning assets means ~2.7 s refreshes.

### Caveats

Restating the generated reports' caveats, plus one from this run:

- Synthetic repos have a single baseline commit, so the constant
  recent-commits(300) walk is under-represented.
- The memory probe is unix-only (`n/a` on Windows).
- Dormant records are seeded on vanished paths; live-path tier-1 scan
  cost shows up in the hunks dimension instead.
- The "weaker hardware" assumption inverted for absolute numbers: the
  ubuntu-latest runner beat the M1 Max on every text-diff dimension
  (files-1000: 95 vs 270 ms) and matched it on binary hashing. Shared
  runners stay uncitable for absolutes (noise, unknown neighbours), but
  the run did its actual job: the exponents agree with the dev machine
  on every dimension.

## 2. Corpus + full suite green on Linux/macOS/Windows

CI run [30634004051](https://github.com/joshdavenport/gitchange/actions/runs/30634004051)
(commit `864fa76`): `test (ubuntu-latest)`, `test (macos-latest)`,
`test (windows-latest)`, and `fmt + clippy` all green — the workspace
suite includes the 42-case apply-correctness corpus
(`crates/gitchange-core/tests/apply_corpus.rs`). Mode-change corpus cases
are unix-only by design; CRLF cases run everywhere under repo-local
`autocrlf=false`. The corpus certifies apply mechanics at libgit2
defaults; on `autocrlf=true` checkouts, checkin filters are git's
concern, not the apply path's (per #27).

Two pre-existing failures were fixed on the way to green, both
test-environment or timing defects, not product regressions:

- `53da290` — test fixtures inherited the host's `init.defaultBranch`;
  pinned to `main`.
- `864fa76` — the engine's `select!` could process a refresh completion
  before requests that preceded it, spawning a redundant third run and
  flaking `last_request_wins_collapses_requests_behind_a_running_job`
  (issue #48); queued requests now fold into the follow-up decision at
  completion (0/150 flakes after, 36/100 before).

## 3. Minimum git version

**git ≥ 2.5**, documented in [README](../../README.md#requirements).
The commit shell-out (ADR 0004) uses only long-stable pieces (`-F`,
`--no-verify`, `--amend`, `GIT_INDEX_FILE`); the floor comes from
linked-worktree discovery. `core.hooksPath` honouring needs 2.9, which
any user configuring it already has.

Full behaviour → test mapping in

### Accepted deviations (decisions, not surprises)

Already recorded on the issues named; restated so this document is the
one place to look:

- **ADR 0005's four performance mitigations are unimplemented by
  design** — measurement-gated (issue #16); this record is the gate
  input. See §1.
- **ADR 0007 info events for going-dormant and 14-day prune are not
  emitted** (#34; #25 scoped the notice plumbing to auto-capture and
  dormant revival). Two emission points in `matcher.rs` + two
  presentation maps, if ever wanted.
- **Error-modal log line is `{title} — first line of detail`**; the full
  multi-line detail does not survive dismissal (#34 — matches the
  prototype, softer than a strict reading of ADR 0007).
- **`Condition` stays watcher-only; `ConditionEnded` never emitted** by
  the Engine in v0.1 (#34); operation/detached pins derive from the
  snapshot in the TUI.
- **Two deliberate softenings vs prototype variant E** (#34), both to
  survive the degraded engine's 5 s polling: the `·` refresh echo
  dedupes on unchanged (files, hunks, conflicted) counts, and an
  *identical* repeated refresh failure neither re-modals nor re-logs
  (cleared by the next successful refresh, so a changed failure still
  modals).
- **ADR 0003's CLI shell-out apply fallback is not implemented** —
  `backend.rs` marks it planned; the apply corpus is pre-built as its
  certification suite.
- **ADR 0006 names an `ApplyFailed` error variant that doesn't exist** —
  apply failures fail soft as notices instead. Doc drift, not a
  behaviour gap.
- **Apply corpus certifies libgit2-default mechanics** — on
  `autocrlf=true` checkouts, checkin filters are git's concern, not the
  apply path's (#27).

### Recorded test gaps

Open, honest holes — none blocks v0.1 (each is a missing assertion over
behaviour that adjacent tests exercise indirectly, or an edge fixture
never built). Filed as issue #50:

1. **ADR 0011's headline consequence unexercised**: no test renames a
   file carrying membership records and asserts old-path dormancy +
   new-path capture to active (text or binary flavour).
2. **Operation-guard breadth**: the commit guard is proven end-to-end
   only for merge; the `RepositoryState` mapping (rebase ×2,
   cherry-pick/revert, `git am`) has no fixture.
3. **`--no-verify` bypass semantics**: plumbed end to end, never
   asserted against a rejecting hook.
4. **Apply-failure abort path** (ADR 0004): no test drives a payload
   that fails to apply to the temp index.
5. **TUI run-loop wiring untested** (`gitchange-tui/src/lib.rs`): op
   echoes, mutation→refresh, `FocusGained`→refresh, hook-rejection
   routing, Align→re-check→commit.
6. **Branch-switch semantics** (ADR 0002): no test carries owned dirty
   hunks across `git switch`.
7. Smaller: atomic write-then-rename / no-`.tmp`-left-behind; "no git
   objects written"; external `git reset` absorption; unowned staged
   hunk capture; `NonUtf8Path` names-the-path + nothing-persisted;
   ADR 0012's non-UTF-8 tree-diff carve-out; `HeadMoveDormancy`
   rendering; post-conflict overlap re-entry; detached-HEAD commit
   unguardedness; watcher-recovery log line; spawn-time degraded
   engine; real-watcher external-git-op integration; Windows hook
   coverage.
