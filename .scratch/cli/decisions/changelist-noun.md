Create/delete take `git branch`'s shape with gitchange's noun: bare `<name>` creates (never activates), `-d`/`--delete` deletes, `-D`/`--force` overrides the delete guard, and the bare command lists. A verb pair (`create`/`delete`) was rejected: the governance line borrows git's vocabulary where an analog exists, and this is the one command with an exact flag-level analog — `-d` refuses / `-D` forces is muscle memory no refusal text has to teach. Borrowing half the grammar would build a false affordance, so the bare form lists too: the read-surface split's own familiarity test points here — an agent _would_ run `git branch` to list branches. The list is the changelist-level slice of `status` — names in user order, `*` on the active one, `unassigned` shown only while it holds the marker (git's `* (HEAD detached)` move) — and has no machine face: `--json`/`--format` refuse, so machine listing stays `status --json` and the two surfaces cannot drift apart on structure. Rename inherits the shape (`-m`; see the rename decision).
