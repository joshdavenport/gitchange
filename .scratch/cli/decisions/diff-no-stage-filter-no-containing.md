The stage dimension is served by the per-hunk `stage` field: a filter flag saves nothing (the snapshot is computed before printing; payload is handled by scoping and `--no-content`), the consumer filters three tokens client-side, and a gitchange `--staged` would collide with git's — same spelling, different operation (git's selects comparison bases; this would filter hunks), the `assign`-not-`add` collision again. Core agrees: stage narrowing exists there only as inline predicates, never a named concept. `--containing` stays a mutation address: a read showing all matches would give one flag two cardinalities across verbs, and the ladder already routes multi-match refusals to explicit IDs. Both are additive later under the schema contract if a real workflow demands them.
