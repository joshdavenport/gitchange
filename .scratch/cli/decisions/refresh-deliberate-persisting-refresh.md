The reads-never-persist decision left the TUI's manual refresh key — a persisting refresh — with no CLI form; op parity owes one, and `refresh` is it: not a read that persists, but a mutation whose whole payload is one persisting refresh, named for the mechanism because capture is only one of its effects (with `unassigned` active it captures nothing and the name stays truthful). `absorb` was rejected twice over: `git-absorb` is a shell-neighbour collision, and ADR 0003 already uses "absorbed" for external git ops entering gitchange's view. The capture-on CLI human's story: capture is refresh-bound everywhere — continuous in the TUI, at each gitchange action in the CLI, on demand via `refresh` — and end-user docs must word the promise that way, never as edit-time magic. `status`'s capture-pending hint names the command, so the surface teaches the resolution at the moment of confusion.
