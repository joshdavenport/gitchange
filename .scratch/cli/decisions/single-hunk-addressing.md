Core widens every assign payload to the whole **index-entry unit** (ADR 0009, issue #106): naming any member moves them all, ownership unchecked, release included. On the CLI that widening is a silent broaden — an address becoming a sweep is the move the `--containing` multi-match decision already rejected, and in a split unit it can take another changelist's hunks. So the CLI refuses a proper subset and the refusal lists every member ID; the retry composes with the existing rules verbatim, adding no flag and no unit-scope ownership variant. This maps the TUI's affordance (the popup names the widened payload before the human acts) to a refusal, per ADR 0015. ADR 0009 is untouched: the CLI never hands core a proper subset, so core's widening no-ops. The refusal is `assign`'s own, not the shared addressing grammar's — staging never widens (unit membership is independent of staging), so `add` inherits nothing. `diff --json` carries no unit field: membership is derivable (a whole-file hunk presents ⇒ every text hunk in the file is a member — facts, not labels), and the refusal teaches the list anyway.
