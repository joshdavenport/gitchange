Every scope — changelist, path, hunk address — chooses which file objects appear; a selected file object is always whole, foreign hunks included, discriminated by the `changelist` field. This is the TUI's dim-not-hide semantics made structural (the two frontends agree on what "scoped to a changelist" means), and it keeps a file object's derivations trustworthy: the whole-file⇒unit-membership rule breaks if a foreign `whole_file` hunk can be filtered out. Composition: paths union; changelist ∩ paths intersect at the file level. A `<path>:<hunk-id>` scope is a selector with validation — a live ID returns the whole file, a not-found, stale, or ambiguous ID refuses — so the verification read is "show me the file and fail loud if my address aged", never hunk narrowing. A valid-but-empty scope is `files: []`, exit `0`; a nonexistent path refuses (exit `1`) — a clean file is an answer, a typo is a wrong question, per the paths decision's wrong-paste promise.
