Core and the TUI commit the unassigned scope like any changelist, and op parity keeps the capability reachable — but the CLI's caller is an agent under ADR 0015's explicit-mode contract, and an agent committing unassigned is almost always skipping the assign step, so the bare command refuses and the refusal is workflow correction: assign-then-commit-named, or the flag. The gate claims no detection — unassigned hunks are recordless (ADR 0016), so there is no attribution to check; its condition is categorical: the addressed scope is the unclaimed pool. The flag borrows `git commit --allow-empty`'s shape and speaks the glossary's term (not a coined "unclaimed"); a `--take-*` name was rejected because commit moves no claims. The TUI stays gate-free — one human's stated intent — the same CLI-stricter-than-TUI split the hunk-addressing decision draws. The agent skill never teaches the flag, mirroring `--take-owned`.
