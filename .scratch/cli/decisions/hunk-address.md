The ID hashes the file path plus the content anchor (the prior-art research's construction, #107), so it is repo-unique and snapshot-scoped — an address, not identity; identity stays with membership records and matching (ADR 0001), and an ID from an aged snapshot fails loud as not-found. Colon because `file:line` / `rev:path` is the address shape agents already know; every symbol is legal in a POSIX filename, so no separator avoids collisions — the parse rule does: the last colon splits, the suffix must be ID-shaped, and a misparse dies as not-found, never a silent misassign. Printed with an `h` sigil (optional on input) so an ID cannot be misread as a commit SHA; unambiguous prefixes of ≥7 chars accepted; identical hunks disambiguate as `<id>/<n>` in file order, jj's spelling. The path prefix is a consistency guard, required — one positional grammar, every argument path-rooted. Degenerate hunks hash a domain tag in place of the anchor — `("whole-file", path)`, `("mode", path)` — so a chmod'd binary's two degenerate hunks stay distinct. The wire `id` carries the `h` sigil too: agents copy addresses out of JSON, so the anti-misread device belongs on the surface they read most.
