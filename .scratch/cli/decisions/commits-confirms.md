The staged-stale warn is a true warn-and-confirm — permission to proceed despite a condition — so ADR 0015 maps it to `--allow-staged-stale`: the allow-shape names the refused condition and is inert when it is absent, and the name speaks the glossary term because CONTEXT.md rules bare "stale" ambiguous (the CLI already carries a different stale, the `StaleHunk` advisory). The stage-all offer is not a warn-and-confirm — it offers a different op before the same commit — so ADR 0015 does not bind and the CLI composes: the empty-payload refusal names `add <changelist>`, which in the empty-payload state is exactly the stage-all op (ADR 0004, #90: the offer stages `○` only, and an empty payload implies no `◑`). A `git commit -a` borrow was rejected as a half-matching analog: git's `-a` is file-scoped, ungated, and always broadens the payload. The warn's align route needs no spelling either — align is a strict subset of the reserved `add` (`○` and `◑` alike go index := worktree, per hunk when addressed), so the refusal text's first resolution is `add`, and the "Staged-stale align" parity gap dissolves. The CLI passes no expected payload to core's commit: drift re-confirmation guards a dialog's promise, and a one-shot command has no prior glance to guarantee — the refresh inside commit is the snapshot.
