`diff [<changelist>] [--] [<path>...]` — the changelist sits where git puts the rev, the analog borrow, and changelist-first matches `add`/`commit`. At most one changelist: gitchange has no range grammar, so a second name reads as a path and fails loud. Resolution is git's rule set: a token matching both a changelist and an existing path refuses, naming `--`; matching neither refuses naming both readings, with changelist candidates listed (gh's error shape). These refusals are exit `1`, not `2` — they depend on repo state clap cannot see. `unassigned` is legal in the slot; `all` refuses — bare `diff` is already the whole view, and accepting it would give one scope two spellings. Bare `diff` shows the whole hunk universe: git's unstaged-only default is not borrowed, because gitchange's `diff` is an inventory with `stage` as a per-hunk field, not a two-tree comparison — an unstaged-only default would silently hide hunks from the read `assign` treats as ground truth. A `--changelist` flag was rejected: it invents a flag where git has a grammar to borrow and breaks the changelist-first positional pattern.
