`create_changelist`, `rename_changelist`, `delete_changelist`, and `switch` change return type from `()` to `OpOutcome` but stay bare locked state writes: an internal persisting refresh was rejected by the switch decision's own argument — it would claim the whole pending unassigned pool, other actors' fresh work included, into the active changelist — so ADR 0005's persisting set stays assign, stage, commit. `OpOutcome` gives the echoes one core home (ADR 0006; the built CLI-composed `switch` echo is a standing drift this cures) and gives notices a carrier: the active-delete notice is a new `Advisory` variant, canonical message in core, CLI-dressed as a stderr `notice:` line like every other advisory. Nothing decided — `switch` to the already-active changelist, `-m x x` — is `echo: None`, silence, exit `0`; git's "Already on" comfort text is not borrowed. The TUI routes the four ops through its op-outcome path, so they join the Log panel's echo stream (ADR 0007). Core work, not built.
