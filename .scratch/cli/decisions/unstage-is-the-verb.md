Git's analog is `restore --staged`, but the borrow is half a grammar: `restore`'s default meaning is worktree restore, an op gitchange does not have, so a visible `gitchange restore` would promise an op that is not there — the false affordance the `changelist` decision warns against, inverted. `stage`/`unstage` is one symmetric vocabulary, and the direction must live in the verb: the TUI's toggle decides by current state, the ambient inference ADR 0015 forbids. Git muscle memory still lands loud: a hidden `restore` subcommand, absent from help, never executes — `--staged` corrects to `unstage`, bare `restore` names raw `git restore` as still valid (exit `2`). (CONTEXT.md's "avoid: stage key and unstage key" is a presentation rule about TUI keys, not ops.)
