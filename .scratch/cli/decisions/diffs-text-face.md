A `--json`-mandatory `diff` was rejected: a verb named `diff` that refuses to diff is the false-affordance move the `restore` decision warns against, and it taxes every invocation with a ceremonial flag. An inventory listing was rejected too — file-level inventory is `status`'s job (the read-surface split), and the `--no-content` decision already reasons that a verb called `diff` promises content. So the text face is git's unified patch, files flat in path order, with gitchange's per-hunk facts (owner, stage glyph, copyable `<path>:<id>` address, ID abbreviated) riding the `@@` header's function-context slot, and degenerate hunks borrowing git's own spellings with the same bracketed suffix — the one thing git cannot print is a changelist-scoped patch, and that is exactly what the scope grammar feeds it. The output is a display: `git apply`-ability is not promised even where the trailer trick preserves it, agents keep using `--json` (the receipts-and-reads doctrine), and neither annotation text nor line shape is a parsing contract. No color, no pager, no tty detection — the TUI is the rich human surface, and plain bytes keep the CLI's loud non-interactive character. `--no-content` stays JSON-only: a content-stripped patch is the rejected inventory face by another spelling.
