`changelist -m <old> <new>` renames, both arguments required: git's one-arg rename-the-active form is the ambient inference ADR 0015 forbids, and it is degenerate when **unassigned** holds the marker. `-M` is not borrowed: core has no clobbering rename, so it would be a non-atomic CLI-side delete-plus-rename posing as one op — rename onto an existing name refuses and names the composition (`-D` the target, then `-m`), so the destructive half stays spelled as the explicit op it is. Rename rewrites every record, live and dormant, and carries the active marker; nothing is lost, so unlike delete it takes no guard and no notice. `--move` is git's long form, borrowed verbatim: #41 rejected `move` as a verb for assign, not as this flag's spelling.
