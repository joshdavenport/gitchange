`diff --json` never emits a flavour enum or rendered placeholder for a degenerate hunk. Mode facts are hunk-attributed (#112, ADR 0017's amendment): each degenerate hunk carries its own `mode_delta` — the `"mode"` hunk its permission flip (never `null`), the `"whole_file"` hunk the type delta (`null` unless the change is a type change) — with no kind discriminator inside the object, because the hunk's own `kind` already names the flavour and a stored discriminator would be a label. The file carries no `mode_delta` slot: the two diffs share HEAD's mode but not their changed side's, so one file-level slot cannot carry both sides' deltas when they diverge in flavour (staged chmod beside a worktree type-swap, or the mirror). The file object carries `binary` and `sides` (per side `null` or `{ oid, size }`, present exactly when a whole-file hunk presents), and the consumer derives binary / type change / empty add-or-delete the same way the TUI's placeholder does; a stored label would duplicate that derivation and drift silently. The hunk carries no `oids` — `sides` holds the same OIDs, and a drift-silent duplicate inside one document is the shared-facts failure. One wire choice on top: modes are the octal strings git prints (`"100644"`, `"120000"`), never raw integers — every other gitchange surface prints modes octal (ADR 0017), and the wire shouldn't disagree with the refusal text agents navigate by. `--containing` never addresses degenerate hunks (no changed lines), so this surface is where an agent learns what one is. #100's corpus pins the sides data for both type-change directions.
