The temp index builds on HEAD's tree, so amending while HEAD is another actor's changelist commit folds the payload into their commit — the cross-contamination the loud-CLI rule exists to prevent, and today's records cannot tell: commits carry no provenance. So commit's aftermath records the last gitchange commit as `{ oid, changelist }`, and `--amend` refuses unless HEAD matches the named changelist's own record; `--allow-foreign-head` is the named override; **foreign** is CONTEXT.md's adjective — another actor's, not the scoped owner's — already used inside core (the foreign-content refusal, the diff view's foreign tagging) and made user-facing for the first time by this flag. The guard fires exactly on the hazard — another actor's commit, an external commit, no record yet — and the happy path (commit, notice a miss, amend) is unguarded; a categorical gate was rejected because it fires on the legitimate case too and teaches reflexive overrides. The guard is the CLI's, not core's: a policy guard against agent misfire, the same CLI-stricter-than-TUI split as `commit unassigned` (the TUI's amend toggle is one human's stated intent). Pushed commits stay unguarded (ADR 0004: standard git territory). Reword is out: gitchange's commit filters a payload through the temp index, and a reword has no payload to filter — wrapping `git commit --amend` would be git re-implementation, not parity — so an empty payload under `--amend` refuses, naming `add <changelist>` and raw `git commit --amend` as the resolutions.
