A typed `<path>` resolves against the caller's cwd — git's own grammar, so tab completion and git habit work from a subdirectory, and at the repo root, where the agent caller sits, cwd-relative and repo-relative are byte-identical. Normalization handles `./`, `../`, and absolute paths inside the repo; what remains is a literal path, never a pathspec — core compares paths exactly and disables backend pathspec matching (`git2_backend.rs`), so wildcards and magic (`:(top)`, `:!`) do not exist here, an unexpanded glob is an ordinary not-found, and the shell's own expansion already feeds the variadic grammar. An argument escaping the repo refuses (exit `1`), named all-or-nothing with the other offenders. A directory argument refuses — the CLI detects the prefix against the snapshot and lists the changed files under it, so the retry is a copy-paste; directory sweeps stay unreserved. Every printed path — `status` text, `diff --json`'s `path`, refusal texts, receipt echoes — is repo-relative regardless of cwd (git `diff`'s convention, not git `status`'s): hunk addresses stay stable strings agents copy between sessions, the JSON never disagrees with the text, and core's canonical `Advisory::message` strings need no cwd parameter. Accepted cost: a subdirectory caller pasting a printed address runs it from the root or prefixes `../`, and a wrong paste fails loud as not-found, never a silent misassign. `-C <dir>` is the borrowed escape for the many-worktree workflow: discovery and resolution behave as if launched in `<dir>`.
