The TUI confirms every delete; ADR 0015 maps warn-and-confirm to a refusal with a named flag. The condition is specific: any membership records, live or dormant — deletion prunes them (ADR 0016) and releases the hunks recordless, and released hunks do not rest: with a real changelist active, the next persisting refresh — the deleter's next op, another actor's, or a running TUI's engine — claims them, into the active changelist or into a split entry's established owner (the entry-unit rule, #106); with capture off they sit unassigned, where a path-sweep `assign` can take them. Either way one actor's hunks can land under another actor's name: the cross-contamination the loud-CLI rule exists to prevent. The refusal names the counts and the mechanism (the TUI confirm's parity, ADR 0016), and the forced receipt carries the release count; neither names a destination (see the mechanism-not-destination decision). Empty changelists delete ungated. `--force` over a condition-naming flag (`--release-claims`) is the analog borrow again; the refusal text still names the condition and counts, so agents navigate the same way. Deleting the active changelist is a notice, not a refusal: **unassigned** becomes active (capture off) per core's rule, and the records guard already covers the dangerous case. Creating an existing name refuses rather than being satisfied: `assign`'s idempotency argument (retry-the-same-command safety) doesn't apply — a refused create needs no retry, and in a shared tree the collision of two actors on one name is worth surfacing loudly.
