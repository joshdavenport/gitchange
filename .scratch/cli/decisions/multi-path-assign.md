Refusals — owned path, nothing to assign, bad hunk ID — are checked against one snapshot before anything is assigned; any offender refuses the whole command, naming them all. This is git's own model (`git add existing missing` is fatal and adds nothing, verified on 2.49) and the safest shape for agents: one refusal is a complete instruction for the next attempt, and a refused command assigned nothing, so the retry is the same command. A path whose hunks already belong to the target is satisfied, not refused — assigns are idempotent. Staleness at apply fails soft per hunk (sweeps only; explicit IDs refuse at validation), but a command that assigned nothing still exits `1`. Cross-path atomicity is validation-level: core applies one locked cycle per path, and the residual race is the accepted collision window.
