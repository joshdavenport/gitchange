Every stage op in core is ownership-scoped — gitchange has no whole-file stage; `git add <path>` is that op, absorbed at refresh (ADR 0003). (Early CLI framing predates this: a whole-file stage once existed; its removal is the more idiomatic shape, and the code and docs are the ground truth.) So a bare path is not a stage target: the CLI address of the TUI's **file row** is the (changelist, path) pair, spelled as the positionals. The changelist is required — defaulting to the active changelist is the ambient inference ADR 0015 forbids — and changelist-first mirrors `commit <changelist>`, so the agent flow reads `assign … --to fix-login` → `add fix-login` → `commit fix-login -m …`. A git-habit `gitchange add src/main.rs` refuses loudly, naming the missing changelist, which teaches the grammar. `◑` staged-stale is included: commit's staged-stale refusal guards commit-time surprise, while an explicit add states that the worktree version is the one meant — the same statement `space` makes.
